Examples

Every card below is a real, working UI built entirely from the HTML you see — tabs, a price calculator, an age gate, a form that submits over the network. Click things, open the console (a few examples log), and hit Show the markup to copy any example straight into your own page.

Same interaction, two ways

The pair below is one button and one panel, written twice. On the Auto-loader tab the markup carries no is= at all — installAutoLoader() adds it for you. On the Explicit is= tab you write it yourself. Both are live; the difference is when the upgrade happens.

No is= on this button or this panel. The auto-loader added is="interactable-button" and is="interactable-section" when the page loaded.

HTML 
<script type="module">
  import "interactably/dist/cdn/revealable.js";
  import { installAutoLoader } from "interactably/dist/cdn/auto-loader.js";
  installAutoLoader();
</script>

<button on-click="#panel.toggle()" aria-expanded="false" aria-controls="panel">Toggle panel</button>
<section id="panel" implements="revealable" hidden>
  <p>…</p>
</section>

An age gate

Raise the age to 18 and the message appears — no button, no script. The guard verb validate() passes when the field’s min="18" constraint holds, and && then runs show() on the consent panel. It triggers on on-change, so the check happens when you commit the value — not on every keystroke.

Three buttons, three panels, no JavaScript. Each button shows one panel and hides the other two — a phrase is just ;-separated verbs. revealable toggles each panel’s hidden state.

Overview. A plain <section> whose visibility is driven by revealable. The other two panels stay hidden until you pick them.

Specs. One phrase, three verbs: #tab-specs.show(); #tab-overview.hide(); #tab-notes.hide().

Sign-up form with a guard

validate() checks the form and stops the chain when it’s invalid. && continues on completion, || continues only on a guard abort: setAttr runs when the form is valid, the alert shows when it is not. The field uses pattern rather than type="email", so the browser only complains when you submit, not while you type.

Thanks — that address looks valid.

Enter a valid email address.

      implements="prevent-default validatable attributable"
      on-submit="#signup-alert.hide(); this.validate().setAttr({name: 'data-signed', value: 'true'}) || #signup-alert.show()">

Order form — the asynchronous seam

on-submit="this.send()" POSTs the form; the response swaps into the receipt and on-response reveals it. This site has no backend, so you’ll see the failure path — the alert — which is the honest behavior. Point requestable-url at a real endpoint and the same markup works; the button disables itself via form[aria-busy="true"] button { pointer-events: none }.

Couldn't place the order.
Show the markup
HTML 
<form is="interactable-form" id="order" novalidate
      implements="prevent-default requestable"
      requestable-url="/api/orders" requestable-method="post"
      requestable-target="#receipt"
      on-response="#receipt.show(); #alert.hide()"
      on-request-error="#alert.show()"
      on-submit="this.send()">

Copy a snippet — the flash is delayable

copyable copies a target's text and marks the button data-copied. It never clears that state itself — the trigger attribute decides. Here on-copy="this.delay(1500).removeAttr('data-copied')" pauses the chain for 1.5 s, then removes the attribute, so Copied reverts to Copy.
