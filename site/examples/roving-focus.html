Roving focus, written out

A combobox is roving focus, written out: every hop is a phrase on the element it leaves from, the ids are positional, and the wrap-around is whatever the last option’s phrase points at. aria-activedescendant is not set because real focus moves — the screen reader announces the option as the current item. The list is static here; a requestable response would regenerate the same ids.

Show the markup
HTML 
<input id="cb-search" type="search" role="combobox" aria-controls="cb-results" aria-expanded="true"
           implements="focusable prevent-default"
           on-keydown="arrowdown: #cb-results-1.focus()"
           placeholder="Search a city…">

    <!-- the list is what a requestable response would return: ids are positional
         and regenerated with each response, so #cb-results-1 is always current -->
    <ul id="cb-results" role="listbox">
      <li role="option"><button id="cb-results-1" type="button" implements="focusable prevent-default"
          on-keydown="arrowdown: #cb-results-2.focus(); arrowup: #cb-search.focus()">Berlin</button></li>
      <li role="option"><button id="cb-results-2" type="button" implements="focusable prevent-default"
          on-keydown="arrowdown: #cb-results-3.focus(); arrowup: #cb-results-1.focus()">Lisbon</button></li>
      <li role="option"><button id="cb-results-3" type="button" implements="focusable prevent-default"
          on-keydown="arrowdown: #cb-results-4.focus(); arrowup: #cb-results-2.focus()">London</button></li>
      <li role="option"><button id="cb-results-4" type="button" implements="focusable prevent-default"
          on-keydown="arrowdown: #cb-results-5.focus(); arrowup: #cb-results-3.focus()">Paris</button></li>
      <li role="option"><button id="cb-results-5" type="button" implements="focusable prevent-default"
          on-keydown="arrowdown: #cb-results-1.focus(); arrowup: #cb-results-4.focus()">Tokyo</button></li>
