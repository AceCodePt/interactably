Make your HTML interactive — without writing JavaScript.

You write plain HTML and Interactably wires it up. start() attaches any element that carries an on-* attribute or implements="…" — no is=, no per-tag setup. No page JavaScript, no framework, no build step.

Quick start

HTML 
<script type="module">
  import { start } from "interactably/dist/cdn/interactably-core.js";
  import "interactably/dist/cdn/revealable.js";
  start();
</script>

<button on-click="#modal.show()">Open</button>
<dialog id="modal" implements="revealable">…</dialog>

One phrase. Clicking the button sends the verb show() to #modal, which implements revealable. start() attaches everything already in the document, and observes for anything added later.

Why

  • 1
    Why should an interaction hide in a .js file when the trigger is right here in the markup? Put the phrase where the action happens: on-click="#pop.show().focus()". The button says what it does — no hunting through handlers.
  • 2
    Why should a receiver be a reference a script holds, when the DOM already has addresses? Ids are the addresses and implements is the capability. #pop.show() reads like English: the element can show because it implements revealable.
  • 3
    Why should debounce, throttle or “only once” mean reaching for an event library? They’re just phrase modifiers: #echo.debounce(300).set(this.value), #tour.once().show(). No imports, no options objects.
  • 4
    Why should “when the request finishes” hide in a callback? The work that takes time owns its moment. The follow-up is a trigger attribute in the markup: on-response="#receipt.show()".
  • 5
    Why should every interaction be a listener you wire, manage and clean up? start() does it for you — one observer binds each element’s on-* at attach and cleans up on detach. Elements declare what they do: on-*, implements, both, or neither.
  • 6
    Why should a failed validation be a dead end? A guard’s preventDefault() stops the chain, and || is the fallback: on-submit="this.validate().send() || #alert.show()". && is the success branch, on whatever element you name.

What it is

A trigger grammar

One attribute per event, and the value is a tiny phrase language. on-click="#pop.show().focus()" reads like a sentence.

Native elements

No shadow DOM, no wrapper elements. Forms submit, dialogs trap focus, details toggle — the verbs are just added on top.

No engine

A pure parser and a pure executor — two functions the attach pass calls. No store, no signals, nothing to learn.

State: three tiers

Authored, live and derived state each live where they belong. The DOM is the store; ids are the addresses; whoever changes B fires A.

An asynchronous seam

Verbs are synchronous and chains never await. When a request lands, the markup says what happens next.

Signatures as strings

Every verb signature is a tsyntax string — the same string type-checks at build time and validates at runtime.

Shipped implementations

Sixteen ready-made capabilities, one per file. Import the ones you use; each registers itself and attaches to the elements that name it.
