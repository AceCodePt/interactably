# Task: Expressions inline in argument position; delete `modifiable-formula` and `compute()`

## Metadata

- **Complexity:** High
- **Priority:** Medium
- **Status:** Ready for Handoff

## Context

Today an author meets two languages on one page: the trigger DSL (`on-input="#total.compute()"`) and the formula (`modifiable-formula="sum('#list .amount')"`). The formula lives on the target as config, is a pull against the whole document, nothing watches its sources, and recomputation is the explicit compute() verb wired by the author. That design has one slot per element. Two cases now need two computations on one element: per-trigger computation ("different trigger, different formula") and masking vs. cleaning (`on-input` formats under the cursor, `on-pasted` cleans a blob once). So the formula moves inline as an expression in argument position: `#total.set(sum('#list .amount'))`, `this.set(replace(this.value, '\D', ''))`. One language. compute() was set with a pre-baked recipe; with no recipe there is no verb. DRY is not a goal; an author who wants the same expression on two triggers writes it twice.

The `.value` ruling (2026-09-17): the element's declared type decides; there is no conversion. type="number"/"range" reads valueAsNumber (empty or NaN is the existing empty-operand / not-a-number error naming the reference, never 0, never silent); type="checkbox"/"radio" reads .checked (a boolean, both spellings work); every other input/textarea/select reads the platform .value string, zeros intact, inputmode declaring nothing; display elements read the type their implementation declares — formattable with a numeric format reads formattable-value as a number, with a date format or no formattable it is textContent a string. + joins when either side is a string, adds when both are numbers; - * / unary - are arithmetic only (a string operand is not-a-number naming the reference); booleans are 1/0; min/max/floor/ceil/round take numbers; sum() totals number-typed elements and errors on the first that is not, naming it as today; count() unchanged; replace() takes a string first argument (lands with formula-replace). No number(), no valueAsNumber token. Dates are parked.

Decisions confirmed with the author during planning (fold into the requirements):
1. `readValue` keeps its exported name (src/core.ts:6, README.md:566/886, formattable.ts:31) — the brief's "rewritten as readTyped" describes the contract, not a rename. Signature becomes readValue(el, property = "value"): number | string | boolean. valueOf and toNumber stay exported for now (deleted in modifiable-inc-dec, not here).
2. Checkbox consequences are documented and the surprising one is tested: the line-item row keeps its shape but the price lives on a number element and the tick on the checkbox; sum() over checkboxes totals booleans as 1/0 (a count of ticked), allowed; a one-line sharp edge that a checkbox's value="..." attribute is unreachable through .value — tested explicitly.
3. FormulaError.message is unchanged. The executor applies the prefix on-<event> on <describeElement(source)>, argument <n> of <verb>(): <message> through logOnce, using the executor's own describeElement; <n> is the 1-based verb-argument ordinal (always 1 — one arg per verb), an expr in an object literal is still "argument 1 of set()" with ", field <name>" appended. EvalContext gains only source and dryRun — no label; the label lives on a FormulaError.label field the executor sets, so tests assert it separately from the reason.

Environment note: the 4 failing smoke tests at HEAD are stale-dist (dist/interactably.js imports auto-wc, which the source no longer uses and which is not resolvable at top level); pnpm build regenerates dist and they recover. Not part of this task.

## Requirements

- [ ] Parser (registry/interactable/parser.ts): Arg gains { kind: "expr"; source: string; position: number } and parseArg falls through to it when the text is not a literal, `this`, a bare `#id` ref, or an object literal — i.e. anything containing an operator, a call, or a `.height`/`.width` read. A bare `#id` stays `ref`, `this` stays `ref`, `#id.value`/`this.value`/`.checked` stay `read`. `position` is the offset of the argument text within the verb's parenthesised content.
- [ ] Parser: READABLE_PROPERTIES narrows to value/checked. `valueAsNumber` leaves it with the parse error `.valueAsNumber is not a property; .value on a number input is already a number`; any other unreadable property keeps the `only value, checked` message. ## Prohibited Patterns

- No second config key, no modifiable-formula-2, no formula-per-event attribute — the expression is in the trigger or nowhere.
- No watching of expression sources (no reactivity); recomputation is the author's trigger.
- No NaN, Infinity, or silent "" from a failed expression; a failed expression is a failed unit.
- No number(), no Number(text) anywhere in the expression path, no reading inputmode, pattern or the text's shape to pick a type.
- Do not keep compute() as an alias; do not keep connectedCallback computing.
- Do not rename readValue — it stays the exported name (src/core.ts:6, formattable.ts:31, README.md:566/886); the brief's "readTyped" wording described the contract, not a rename.
- Do not change FormulaError.message construction — the executor applies the label prefix; EvalContext gets no label.
- No code comments beyond the brief's.
